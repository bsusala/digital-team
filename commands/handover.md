Create a session handover by generating `docs/CONTINUATION.md`.

## Instructions

1. **Detect project type** and read the version source:
   - Rust: `Cargo.toml`
   - Node: `package.json`
   - Python: `pyproject.toml` or `setup.py`
   - PHP: `composer.json`
   - Other: check for any common manifest file

2. **Gather context** by reading (skip any that don't exist):
   - The version/manifest file identified above
   - `CHANGELOG.md` (recent changes — focus on entries since last CONTINUATION update)
   - `docs/CONTINUATION.md` (existing document — use as style reference and baseline)
   - `docs/ROADMAP.md` (strategic direction, if it exists)
   - Recent git log (`git log --oneline -20`)
   - Open GitHub issues (`gh issue list` — skip if no remote)
   - The auto-memory file at the path shown in your system prompt
   - **This session's own conversation** — what was decided, tried, abandoned, and left
     unfinished. On a new project this is the only source that exists, and it is always
     the primary one: the files above record what the project *is*, the conversation
     records what just *happened* to it.

3. **Generate `docs/CONTINUATION.md`** following the established style (or create fresh if none exists):
   - Header: project name, version number, today's date
   - **Completed Work**: brief bullet summaries of what's done
   - **Current Work**: what's actively being worked on with details
   - **Next Up**: what comes after current work
   - **Key Design Decisions**: table of important choices and rationale
   - **Key Files**: code listing with one-line descriptions
   - **Open Issues**: table from GitHub issues (if available)
   - Keep it factual and concise — this is a reference doc, not prose

4. **Write the file** using the Write tool. Create `docs/` directory if it doesn't exist.

5. **Show a brief summary** of what was generated (don't dump the full content).
